# Agent instructions for mineflayer

## Read first

Read [CONTEXT.md](CONTEXT.md) before changing bot lifecycle, plugins, protocol versions, tests, or cross-repository dependencies. Read [SECURITY.md](SECURITY.md) before handling Microsoft authentication, tokens, server credentials, packet captures, plugin code, child processes, or untrusted servers. Read [docs/CONTRIBUTING.md](docs/CONTRIBUTING.md), [docs/README.md](docs/README.md), and [docs/llm_contribute.md](docs/llm_contribute.md) when the change affects public behavior, tests, or documentation.

## Repository conventions

- index.js is the package entry and lib/loader.js loads the core plugins. index.d.ts is the TypeScript API contract.
- docs/README.md is the canonical README. Root README.md is ignored and generated by prepublishOnly; do not maintain a second hand-edited copy.
- lib/version.js is the exact tested-version list. Keep version guards, minecraft-data, node-minecraft-protocol, prismarine-chunk, prismarine-item, and prismarine-physics compatible.
- This fork's package.json deliberately uses local file dependencies for sibling repositories and vendor/minecraft-data. That topology is for this checkout; normal npm consumers install published packages.
- tests are divided into internal node-minecraft-protocol tests, external Vanilla-server tests, and focused regression/resource-limit tests.

## Safe change rules

- Mineflayer should usually report recoverable bot failures through its established event/callback conventions instead of crashing a bot. Preserve existing error behavior and asynchronous cleanup.
- Plugins must clean up listeners, timers, sockets, child processes, and spawned test servers. Do not leave account tokens, generated server files, or private logs in the tree.
- Put release-specific behavior behind the smallest version/feature guard. Keep 26.2 and 26.3 behavior compatible with all earlier versions in lib/version.js.
- Cross-repository protocol/data changes must be validated at the owning repository first, then exercised through Mineflayer's integration paths.
- Do not weaken authentication, packet limits, parser checks, or server cleanup to make a test pass.
- Public API or TypeScript changes require matching docs and declarations.

## Commands and completion

The package requires Node.js 22 or newer. From the repository root:

    npm install
    npm run lint
    npm test

Focused commands include npm run mocha_test -- -g <pattern> and npm run perf:baseline. External tests may require a local Vanilla server and are separate from the internal suite. Do not put Microsoft credentials in shell history, fixtures, logs, or commits. Before handoff run git diff --check, inspect local file dependencies, and record which test tier was run.


## Reproducing this fork's release work

The 26.2/26.3 commits are newer than the published 4.39.0 package. npm install from the registry does not reproduce this source tree. The validated local setup requires the adjacent repositories at ../node-minecraft-protocol, prismarine-chunk, prismarine-item, and prismarine-physics plus vendor/minecraft-data. Check package.json and package-lock.json before changing that topology.

The research record in docs/documentation-research.md is the citation source for cross-repository documentation decisions; update it when a source or governance channel changes.
